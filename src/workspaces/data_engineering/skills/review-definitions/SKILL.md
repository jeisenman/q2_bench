# Review definitions

Use available tools to inspect the actual pull request, author, diff, schema
checks, source pins, formal evidence, and downstream impact. Treat formal
contradictions as information. Identify machine-generated text.

A reviewer must not approve their own change. Do not claim that a check,
approval, merge, or rejection occurred without evidence. Reject reasons are
`incorrect`, `duplicate`, and `out-of-scope`.

Get the user's explicit instruction before you post a review, merge, or close
a pull request.
