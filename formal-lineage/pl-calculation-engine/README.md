# Calculation engine parser and dependency scaffold

Parse existing C#/TypeScript implementations into the shared method catalog.
Keep engine dispatch, input contracts and call candidates pinned to source.
Source is not rewritten and syntax discovery remains non-executable.
See [project.json](project.json) for the reviewed engine commit.

## Dependency inventory

[Direct dependency list](dependencies.md) lists all declared direct package
versions. The reproducible Go inventory also retains every npm lock instance,
outgoing dependency/peer/optional edge, project reference, MSBuild condition,
SDK declaration and exact source digest.

```bash
go run ./cmd/agentbench formal-lineage dependencies \
  --project pl-calculation-engine --root ../pl-calculation-engine \
  --commit 41616184ea208c601b37918bf942230d6921a7ea \
  --output var/lineage/pl-calculation-engine-dependencies-20261103/inventory-v2.json
```

This writes the report and exits nonzero because full closure is unresolved.
The inventory contains seven .NET projects, nine concrete project references,
two additional conditional MSBuild item references, 22 NuGet declarations
(12 distinct package/version pairs), 33 npm declarations (31 distinct pairs),
and 934 npm lock instances (760 distinct pairs / 649 names). Build SDK:
`Microsoft.Build.Traversal/2.0.24`.

[Complete generated inventory](dependency-inventory.json)
is retained for PR review. Regenerate it using the pinned command above;
the generated runtime copy remains under `var/lineage/`.
Lock entries describe package resolution, not actual runtime usage. Package
edges are separate from method calls and dataset lineage.

## Resources and remaining gaps

Source, engine/service projects, native test vectors and .NET SDKs 9.0/10.0 are
available. The core engine and C# service have no direct external NuGet package
references. Test utilities and tests introduce external packages; TypeScript
projects have separate build dependencies.

The local package sources currently expose public NuGet; CI references an
Azure Artifacts feed. No authenticated restore has been performed, so the
NuGet transitive closure remains unknown. The engine test
`Configurations/Configurations.json` is absent; its sample is available.
Native tests may need that configuration and private feed access. No secrets
or test configuration are generated by this scaffold.

C# type/overload binding, decimal/null/overflow/exception semantics and
TypeScript number/coercion semantics need explicit lowering and native runtime
oracles. No equivalence or whole-engine proof is claimed.
