Treasury D2P: “Unlikely” cannot be selected

Confirmed contradiction

The first confidence rule requires the same day difference to be more than 10 days before close and more than 120 days after close. Those ranges do not overlap.

days < −10 AND days > 120

Intersection = ∅. There is no finite numeric value that makes both conditions true.

What the comment describes

An outside-window rule: more than 10 days before close or more than 120 days after close.

What Databricks actually returned

With an account present, both −11 days and 121 days returned “Likely.” The observed result matches the source’s AND rule.

F.when((F.col("FirstRefreshMinusCloseDate") < -10)
       & (F.col("FirstRefreshMinusCloseDate") > 120), "Unlikely")
 .when(F.col("CoreAccountId").isNull(), "No Core Account Match Found")
 .otherwise("Likely")

Comparable loans: missing-feature handling depends on order and history

Confirmed transform defect

The documented rule says to null features whose missing fraction exceeds the cutoff. Both term features in this two-row input are 100% missing. At the source cutoff of 33%, the original helper keeps one null but silently fills the next with zero.

cols_to_keep = col_list
for col in col_list:
    ...
    cols_to_keep.remove(col)  # also changes the list being iterated

Removing an entry shifts the next feature past the iterator. Reversing the selectors reverses the result. Reusing the same list object changes the output again, even with identical input rows.

Suspicious boundaries that do not establish a defect

5 clauses · fixture mutation screen

Some strict/inclusive changes returned the same value in the generated fixtures. A surviving mutation can reflect equal branch outputs at the cutoff, rather than a missing boundary row.

  • Three utilization/credit-size clamps. At the cutoff, returning the cutoff and returning the input can produce the same value. For example, WHEN x >= 1.1 THEN 1.1 ELSE x and a strict > condition agree when x = 1.1.
  • Two versions of the tier-price calculation. When volume equals the upper limit, (upper − lower) × price and (volume − lower) × price coincide at that boundary.
